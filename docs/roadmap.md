## Тюнинг волны + сейф вкусов (зафиксировано 30.09.2026)

Контекст: `refresh_tastes` считает `пользователей = строки UserCredential`
(opt-in сейф), а не всех `MediaUser`. Navidrome отдает `starred/плейлисты`
только владельцу, поэтому мозг ходит под паролем самого юзера
(`taste_import.import_user_tastes` + `SubsonicAuth`). Пароль мозг видит
только в момент ввода — отсюда ручной `Запомнить пароль`.
Ошибки ночного синка — это `auth fail` сейфа (ключ `env/db`, расшифровка,
`external_id`/логин, недоступность сервера), смотреть
`Задачи и логи -> refresh_tastes`. Слово `протух` = `auth fail`, а не expiry.

Решения зафиксированы: авто per-user + глобальные лимиты; MVP авто только
п.1 (повторы + novelty + forgotten_days); панель `Сейчас применено` только
в `Настройках` (бейджа на `/wave` нет).

## Настроения: разбор и план (14.10.2026)

Аудит двух вопросов: **(1) угадывает ли мозг настроение по скипам?**
**(2) строит ли дерево настроений / распределение для плейлистов?**
Ответ на оба — **нет**. Ниже что есть на самом деле и что предлагаю
сделать. Ссылки на строки — чтобы проверялось глазами, не на слово.

### Что есть (проверено в коде)

**1. Настроение по скипам не определяется.** `infer_auto_mood()`
(`wave.py:605`) берёт центроид energy/valence по трекам сессии и мапит в
канонический код — это звук, а не поведение. Выборка сессии скипы
исключает by design: `wave.py:2432-2438` берёт только `play|complete|
replay|like`. Второй вызов, `rerank_pool` (`wave.py:1516`), берёт сессию из
`PlayHistory`, где колонки `action` нет вообще (`db/models.py:224-234`) —
скипов там не видно по определению.

**Скипы при этом не выброшены** — они работают другой линией,
`session_drift` (`wave.py:424`): 3/5/7 скипов подряд в хвосте →
mild/moderate/strong → энергия −0.1/−0.2/−0.3, темп −10/−20/−30; 3+ скипа
жанра → временный бан жанра на этот запрос; скипнутые треки выкидываются
из кандидатов. Зеркальная ветка `warmth` на хвосте
like/replay/complete/seek_back → энергия и темп **вверх**. Итог: скипы
крутят **громкость и курс**, но никогда не порождают ярлык вроде
«грустное». Отдельно `skip_model.py` предсказывает P(скипнуть трек <30с)
на кандидата — это пофильтровка, не детектор настроения; включается от
≥5000 размеченных / ≥200 ранних скипов, иначе эвристика `skip_risk()`.

**2. Дерева/распределения нет.** Поиск `tree|иерархи|hierarch|taxonomy` —
0 совпадений. Что есть вместо:

- `MOOD_PRESETS` (`wave.py:120`) — 9 пресетов **плоской линией**:
  energetic/happy/calm/sad/dark/aggressive/chill/relaxed. Каждый = жёсткий
  фильтр (`energy_min`, `tempo_max`, …) + семейство муд-лейблов. Один
  уровень, без вложенности.
- Контраст внутри очереди — `used_moods` (`wave.py:1000, 1264-1273,
  1366`) + `mood_penalty = [0.03, 0.06, 0.10]`: считает, сколько раз код
  уже встретился в **текущей сгенерированной пачке**, штраф нарастает по
  повторам. Это «не топчься в одном настроении подряд», не профиль вкуса.
- Настроение-руки — `mood_boost_for` (`wave.py:1705`): `TasteArm` с
  `kind='mood'`, контекст = группа часов, exploit+explore по pulls/reward.
  Единственное место, где настроение реально **учится**. Хранит скаляр
  на имя — не распределение.
- `mood_vector` — 4-мерное пространство `{energetic, valence, arousal,
  calm}` из `audio_analysis.py:353`, лежит в `TrackFeatures.mood_vector`.
  Почти мёртвый: потребителей два (`wave.py:1154`, `wave.py:2027`), и оба
  читают оттуда **только `ai_sentiment`**. Четыре аудио-координаты в
  скоринг не попадают вообще.
- Плейлисты настроением не собираются — `generate_daily`
  (`api/playlists.py:256`) = per-user cold-start + оркестратор волной. Единственное
  участие муда — в AI-генераторе `playlist_ai.py:122-138`, где таргет ищется
  подстрокой (`if "энергич" in query`). Балансировки нет.
- Кластеры — `TrackCluster` kmeans даёт `top_genres` + `avg_energy`
  (`api/clusters.py`): распределение жанров/энергии, не настроений. На
  сиды волны, не на композицию плейлиста.
- В вебе тоже не распределение — `taste.py:839` отдаёт
  `"moods": [{name, count}]` топ-12, а `web/src/app/users/[id]/page.tsx:233-249`
  рисует **чипсы с числами без полосок**, в отличие от жанров/артистов,
  где ширина полоски пропорциональна весу (`page.tsx:261-267`).

### Предлагаю сделать (в порядке «дёшево → дорого»)

- [ ] **M1. Включить 4 координаты `mood_vector` в скоринг.** Первый шаг,
      самый дешёвый: данные уже считаются и лежат в базе, нужен только
      доступ. Точка врезки — `score_candidates`, блок `wave.py:1145-1179`,
      где уже стоят `cluster_c` (1147) и `lyr_c` (1152): вектор настроения
      ложится между ними. Гипотеза: сходство с центроидом сессии по
      осям `{energetic, valence, arousal, calm}`. Откат — фиче-флагом по
      образцу `_clap_weight()` (`wave.py:549`).
- [ ] **M2. Агрегат mood-профиля по пользователю.** Центроид + дисперсия
      по 4 осям в окне N дней, срез по контексту (час × будни/выходные) +
      доля ранних скипов внутри каждой ветки. Сырьё на месте
      (`TrackFeatures.mood_vector`, `PlayEvent`), привычка агрегировать в
      `taste.py` есть — не хватает слоя. Легло бы в
      `services/mood_profile.py` по образцу `services/drift.py` (недельный
      `TasteSnapshot`).
- [ ] **M3. Иерархия настроений.** `MOOD_PRESETS` плоский; если «грустное →
      меланхоличное / тёмное» должны быть детьми, а не соседями, структуры
      нет. Решить: статический 2-уровневый словарь (настроение → дети +
      веса наследования) или переиспользование `TrackCluster`. Осторожно:
      семейства лейблов внутри `MOOD_PRESETS` уже работают как псевдо-
      иерархия — не задвоить.
- [ ] **M4. Распределение в сборке плейлиста.** Сейчас `mood_penalty`
      штрафует повторы внутри очереди; распределение по своим веткам при
      выборе треков не учитывается. Идея: сначала раскладывать целевые
      пропорции настроений (профиль из M2 × контекст), потом набирать треки
      по ячейкам (ветка настроения × бакет энергии), а существующую
      механику `used_moods` оставить мягким ограничением внутри ячейки.
- [ ] **M5. Скипы → настроение (осознанно осторожно).** Сейчас в
      `infer_auto_mood` скипов нет. Если нужно «скипаю энергичное → хочу
      спокойное» — работа отдельная. Оговорка: ранний скип чаще значит
      «не этот трек», а не «не это настроение». Предлагаю скип подавать не
      в настроение, а **приором на вектор**: сдвигать центроид в сторону
      того, что юзер не скипает, малым весом и с отдельной метрикой.
- [ ] **M6. Показать распределение в UI.** `users/[id]` — рисовать настроения
      полосами по весу, как жанры/артисты. На `/wave` — какая ветка сейчас и
      её доля (`auto_mood` и `mood_source` уже отдаются, `wave.py:2777-2782`).
