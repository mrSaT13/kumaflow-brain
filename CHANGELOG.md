# Что нового в KumaFlow Brain

Живой список изменений по версиям. Полный текст — в коммитах `main`.

## 0.3.32

Плееры правят свой тюнинг сами, без админа.

- **`PUT /api/settings/rec-tuning` для владельца.** Не-админ со скоупом
  `sync` пишет личный оверлей (`user_id` == владелец токена): мобила
  выставляет свои `character.era_weight` / `character.depth`. Глобал
  без `user_id` и чужие оверлеи — по-прежнему только админ (403).
  Чтение `GET` доступно любому аутентифицированному (секретов в числах нет).

## 0.3.31

Полный список любимых артистов для автоподписок загрузчика.

- **`GET /api/users/{user_id}/favorite-artists?limit=2000`.**
  Все артисты по лайкам (`{name, likes}`, сортировка по лайкам вниз,
  при равенстве — по имени) без потолка top-40 из `/profile`.
  Дубли регистра/пунктуации схлопываются тем же каноническим ключом,
  что и подписки Library Sync. Пусто → `{"artists": [], "total": 0}`.
  Загрузчик уже переписан под эндпоинт, со фолбэком на старый `/profile`.
- **Library Sync: пустой токен не затирает сохранённый даже при явно
  переданном `""`.** Раньше защита работала, только если ключ отсутствовал
  (на это полагался веб-UI); теперь `""` тоже означает «оставить прежний».

## 0.3.29

Новинки от подписок доезжают до плеера целиком.

- **Треки в уведомлении.** Уведомление о поступлениях несёт `meta.tracks`
  (`id` на стороне медиа-сервера + название/артист, до 50) — плеер качает
  в офлайн точечно, без гадания по названиям. Старые строки без `meta`
  читаются как раньше.
- **Фильтр немузыки везде.** Скиты/интро вырезались только из волны, а
  радио открывалось топом-скитом и подборки его пропускали. Единая
  `drop_non_music_tracks()` для волны, обоих радио и `rerank_pool`
  (опорный трек трек-радио не трогаем — его выбрал пользователь).
- **Ответ подписки.** Возвращаем и `artist_external_id` — плееру есть
  чем точно матчить.

## 0.3.28

Стабильность связки с внешним сервисом и честность умных плейлистов.

- **Настройки внешнего сервиса.** Токен больше не затирается при
  сохранении формы с пустым полем (пустое = оставить прежний), а проверка
  соединения подхватывает сохранённый токен — повторный ввод не нужен.
- **Подписки без дублей.** Дедуп по каноническому ключу имени
  (`AC/DC == AC-DC == ac dc` — одна запись, один уход наружу), ответ
  сервиса сверяется тем же ключом, локальная строка обновляется на
  каноническое имя + id на стороне сервиса. Неоднозначное имя — честная
  ошибка в `provider`, а не молчаливое `ok`.
- **Уведомления точнее.** Подписчики ищутся сначала по id на стороне
  сервиса (когда он прислан в событии), затем по ключу, затем по старой
  норме — старые строки продолжают находиться.
- **Холодные слушатели.** Умные плейлисты пользователей без данных
  строились из одного окна общей выборки и совпадали почти 1в1. Теперь
  окно поворачивается по стабильному хешу юзера (наборы разные, тёплых
  не трогает). В описание автоплейлиста пишется владелец («для @user») —
  в общем списке видно, чей он.

## 0.3.27

Library Sync — связка с внешним сервисом-поставщиком треков.

- **Подписки на артистов.** Игрок присылает «следи за артистом» —
  `POST /api/library-sync/subscriptions`, мозг сохраняет локально
  (таблица `artist_subscriptions`) и ретранслирует наружу.
- **Приёмник событий.** `POST /api/library-sync/events`: скачанное →
  быстрый скан Navidrome → точечный апсерт треков → уведомления
  подписавшимся («новые треки — уже в библиотеке»). Тяжёлое — в воркере.
- **Настройки → Library Sync.** Адрес + токен, токен наружу не отдаётся.
  Нейминг нейтральный: провайдер нигде не упоминается.

## 0.3.26

Фикс позора «в стиле Drowning Pool играет Coldplay».

- **Фолбек похожих больше не врёт.** Если у сида нет ни жанра в базе,
  ни кластеров — возвращаем честно мало/пусто, а не топ библиотеки.
  Именно так Linkin Park / Scooter / Coldplay выдавались за «похожих»
  на всё подряд. Добивка топом теперь только с жанровым пересечением
  ИЛИ общим кластером (кластерные артисты — одним запросом).
- **Якорь волны тянет треки своего артиста.** Пул был «кластер + векторы
  + случайные» — самого артиста мог не содержать вообще, и скоринг по
  вкусу поднимал топ библиотеки. Теперь до 50 топ-треков артиста якоря
  идут третьим слоем пула.
- **Лог `artist_radio`.** Пулы и списки похожих/хопа-2 видны в
  `docker compose logs backend` — следующий «мимо» диагностируем по логу,
  а не по скрину.
- **Кружки «похожие» на странице артиста — та же ложь, тот же фикс.**
  `GET /api/library/artists/similar` дублировал баги (точный регистр,
  точный IN, фолбек топом по числу треков) — теперь общая функция
  из радио, фолбека-топом нет.
- **Сабстринг жанров.** Тег `numetal` одним словом не матчился ни с
  `nu metal`, ни с `alternative metal` (токен `metal` ⊂ `numetal`, порог
  длины 4 против `pop ⊂ popular`).
- **Кэш векторного добора** по сидам на 15 минут — волну докручивают
  часто, seq-scan каждый раз ни к чему.
- **Канон жанров на входе.** Рваные теги (`numetal`, `Nu Metal`,
  `hiphop`) канонятся при скане/импорте (`nu metal`, `hip-hop`),
  старые строки правит backfill при старте бэкенда. Корень проблемы,
  которую раньше чинили сабстринг-матчем.
- **Эпоха и хиты/дип-каты.** Профиль отдаёт `preferredDecades`
  (любимые десятилетия по лайкам), скоринг даёт `era_weight × decade`
  (дефолт 0.05, без года — 0, а не штраф). Ручка `depth` (−1..1):
  +1 тянет к заигранному, −1 — к редкому, шкала ±0.1. Чипы `era/depth`
  в разборе трека.
- **Тренд в сводке.** `GET /api/wave/feedback` отдаёт `trend`: текущие
  7 дней vs предыдущие 7 (п.п., минус у скипов = лучше) + по источникам.
  Без истории — `trend: null`, а не нули.
- **Авто-веса характера.** `auto_tune` при `auto.character` крутит
  `jitter` (скипы — разболтать +0.02, всё хорошо — −0.01) и
  `timbre/knn_weight` (×0.9 при скипах). Остальные веса — только руками:
  по сигналам недели они честно не атрибутируются.
- **Mood-профиль.** Новый `services/mood_profile.py`: твой центроид
  в 4-осевом муд-пространстве за 30 дней (лайк ×3, реплей ×2, дослух
  ×1.5, затухание 14 дней, минимум 5 треков с анализом). Мягкий приор
  в скоринге (`character.mood_profile_weight`, дефолт 0.04, чип
  `mood_prof`): без пилюли волна играет твою пропорцию, с пилюлей она
  по-прежнему побеждает (режет пул жёстко).
- **MMR-финал.** Внутри `select_diverse` жадный добор
  `скор − λ·похожесть_на_выбранные` (артист 0.5 / жанр 0.3 / муд 0.2,
  муд — только без пилюли). Капы и floor остаются жёсткими рамками —
  MMR торгуется внутри них. Ручка `playlists.mmr_lambda` (дефолт 0.1,
  0 = выключен, поведение 1в1). Радио не тронуто: там круг по артистам
  уже держит разнообразие.

## 0.3.25

Радио растёт вширь, как у ЯМузыки: второй хоп + добор по звуку.

- **2-й хоп похожих.** Пул был «свои + 6 похожих»: похожие на Slipknot
  (когда Slipknot пришёл из FFDP-радио) не добирались никогда. Теперь
  топ-3 артиста 1-го хопа раскрываются (`radio_second_hop_artists=3`,
  с каждого до `radio_second_hop=2` имён), треков со 2-го хопа — вдвое
  меньше, чем с 1-го. 0 в любой ручке = выключено. В ответе новое поле
  `similar_artists_2hop`.
- **Векторный добор в пул.** Соседи сидов по звуку, а не по имени жанра:
  9-D вектор librosa (темп/энергия/валентность/спектр) k-NN к конкретным
  сидам (0.6) + тембр chroma 12-D + форма MFCC (0.4). Выборка — 2000
  играбельных, сходство в памяти. Ловит тот же материал при рваных тегах.
  Ручка `radio_vector=60` (0 = выкл). В трек-радио и в якоре живой волны —
  тоже (кластер → векторы → случайные).
- Ручки в «Настройки → Волна», дефолты = поведение с запасом, всё
  best-effort: добор не валит радио целиком.

## 0.3.24

Три жалобы юзера — три фикса: синк падал, любимые артисты банились,
радио стартовало не с того.

- **Синк больше не падает на дублях.** `sync_from_mobile` слал двойной
  INSERT при повторе «Linkin Park» в одном пакете (сессия
  `autoflush=False` не видит pending) → `UniqueViolation
  artist_bans_pkey` → вся сессия в rollback и все следующие синки с
  «This Session's transaction has been rolled back». Теперь pend-множество
  банов + `begin_nested` на вставку (дубль = не ошибка), а API делает
  `rollback` и отдаёт первопричину без мусора про сессию.
- **Любимые артисты не банятся.** Автобан «3 дизлайка = бан» не смотрел
  на лайки: 17 ♥ / 400+ plays + 3 пропущенных трека = бан всего артиста
  (Limp Bizkit в топе — в бане). Теперь при живых лайках автобан требует
  минимум 5 дизлайков И больше дизлайков, чем лайков. Яндекс-импорт больше
  не превращает каждый disliked-артист в жёсткий бан, если локально есть
  лайки. Разбан уважается: старый список с другого устройства не воскрешает
  бан (проверка надгробий `ban`).
- **Радио по артисту: опорный трек — первым, похожих — больше.**
  `_similar_artist_names` матчил жанры только точным `IN` — при рваных тегах
  («Metal» vs «Alternative Metal») находилось 1-2 артиста и радио шло
  «по кругу из двух». Теперь мягкий матч по токенам жанра + добивка
  топом по plays с тем же жанр-токеном. `artist_radio` гарантирует:
  первый трек — топ выбранного артиста (до и после дуги/круга), скоринг
  не выкидывает пул молча (добивка невиданным).

## 0.3.23

Четыре бага/косяка, которые пользователь нащупал руками: вкус затирался
между клиентами, кнопки тюнинга ничего не делали, стиль радио терялся, а
«Боевое» пускало быстрый мажорный EDM.

- **Слепок вкуса — по источникам.** Раньше он был ОДИН на всех клиентов:
  кто последним прислал профиль — тот и записал, предыдущего стирал.
  Яндекс-импорт шёл как «mobile» (не передавал `source`) и с пустым
  `preferredGenres` стирал мобильные жанры, а со своим `preferredArtists` —
  мобильных артистов. Теперь у каждого источника своя корзина
  (`TasteProfile.sync_profiles`), а поля `mobile_*` — **слияние** всех
  корзин (их читает скоринг): жанры/артисты по максимуму веса, списки —
  объединение, счётчики — сумма. Источник по-прежнему может очистить
  СВОЁ (прислал пустым), но не чужое. Данные, накопленные до разделения
  корзин, не теряются: первый же синк относит их к тому, кто писал последним.
- **Пять кнопок тюнинга перестали быть пустыми.** `pool_limit` (2000),
  `score_window` (800), `collab_extra` (200), `seed_limit` (5),
  `fatigue_days` (7) — значения сохранялись, но их никто не читал: пул,
  окно скоринга, добор коллаборативных, число сидов и окно усталости были
  зашиты константами. Теперь читаются из тюнинга (дефолты = прежние
  значения, поведение 1в1).
- **Радио-сид участвует в волне.** Сохранённый сид (`wave_seeds`) жил
  только в капсуле и в очереди одного запроса: как только очередь радио
  доигрывалась, волна возвращалась к сидам вкуса — стиль («как у Bodies»)
  терялся. Теперь сид — якорь волны (первый сид: центроид звука, k-NN-опоры,
  тембр, кластер), а пул добирается его кластерными соседями
  (`playlists.radio_cluster_pool`, по умолчанию 300). Сброс — `DELETE
  /api/wave/seed`, как и раньше. Якорь живёт 12 часов (`RADIO_SEED_TTL_H`):
  капсула «последнее радио» помнит долго, а рулить волной старый сид не
  должен.
- **«Боевое» ≠ «бодрое».** В семейство лейблов пилюли входит «энергичный»,
  а это ровно energy — быстрый мажорный EDM проходил наравне с metal. У
  пилюли появились рамки: `valence_max 0.55` (мажорное — мимо) и
  `arousal_min 0.7` (спокойное мощное — мимо).
- 12 новых тестов (258 всего).

## 0.3.22

Поток волны: содержание (что играть) — отдельно от формы (как играть).

- **Тембр в скоринге.** `TrackFeatures.mfcc_summary` (13 средних MFCC) и
  `chroma_summary` (12-D профиль гармоник) считались анализатором и лежали в
  базе, но рекомендатель их не читал — только дедуп. Теперь тембр (гармоника +
  форма, c0 выкинут, z-норма внутри трека) сравнивается с материалом сидов и
  текущей сессии: `comp.timbre`. Один жанр — разный материал: ударные против
  струнных теперь видны.
- **k-NN по эмбеддингам.** Волна сравнивала кандидата только с ЦЕНТРОИДОМ
  (среднее) сидов/сессии: трек, похожий на ОДИН конкретный играющий трек, но
  не на среднее, балла не получал. Теперь считается среднее top-k косинусов к
  конкретным опорным трекам (сиды + сессия) — `comp.knn`. Опоры: CLAP-аудио
  векторы, фолбэк — 9-D вектор librosa.
- **Попарное ограничение потока.** Дуга (`order_by_wave_arc`) задаёт ФОРМУ
  пачки, а соседние треки теперь ещё и не шокируют темпом и тембром:
  `_smooth_flow_order` переставляет соседей по суммарной совместимости, но
  только если своп не рвёт энергетическую дугу (`|Δenergy| < flow_energy_max`).
  Тональность по-прежнему сглаживается отдельно.
- **Ручки в «Настройки → Волна»:** вес тембра и вес k-NN (группа «Характер
  волны»), проходы/допуск/веса потока (группа «Плейлисты и раскладка»). Вес 0
  выключает сигнал — волна работает как раньше.
- **`ml.search_by_embedding` без N+1:** треки для выдачи грузятся одним
  запросом вместо `db.get` в цикле по всей таблице эмбеддингов.
- 14 новых тестов (246 всего).

## 0.3.21

Три бага, которые тихо портили персонализацию.

- **Кламп скора больше не решает порядок.** Сумма потолков (~2.6) упирала
  почти всю пачку в `1.00`, и треки с разным качеством шли в порядке обхода
  пула — то есть фактически случайно. Теперь ранжирование идёт по сырому
  `score_raw`, а `score` (0..1) остаётся только для показа. Раньше это
  задевало и дугу волны: вершина строилась по «случайному» порядку.
- **В базу пишется скор модели, а не растянутый min-max.** `spread_scores`
  размазывал окно для показа, и `rec_feedback.mark_served` записывал
  именно эти размазанные числа — цикл обучения получал неверные значения.
  Теперь в `RecommendationFeedback.score` лежит сырой `score_raw`.
- **Синк с пустым профилем больше не стирает вкус.** `apply_delta` звал
  `sync_from_mobile` с профилем `{}` на каждой волне с дельтой оценок, а
  отсутствующие ключи профиля считались «пустыми» — и мобильный слепок
  (жанры, артисты, лайки, дизлайки, баны, счётчики) затирался на ровном
  месте. Теперь «не прислал» = «не трогаем», «прислал пустым» = «очисти».
- **Кэш тюнинга перестал быть мёртвым.** Он был, но вызывался только без
  `db` — а весь код читает тюнинг с сессией: два чтения `AppSetting` на
  каждый запрос волны. Теперь кэш (20 с) работает, запись его сбрасывает.
- 7 новых тестов.

## 0.3.20

Скип-предиктор теперь обучается сам и виден со стороны.

- **Крон «Skip-модель» (раз в час).** Модель `P(скип<30с)` обучается на
  истории `PlayEvent` всех пользователей. Раньше она появлялась только когда
  кто-то позовёт волну (и тогда же на каждый запрос пересобирался датасет) —
  теперь переобучение идёт по расписанию, а «ждать запроса» больше не нужно.
- **TTL отрицательного кэша — 10 минут** (как и задумывал исходный код: там
  стоял hack с `+600.0`, но он не срабатывал из-за guard'а `hit is not None`).
  Модель не отстаёт от данных: как только наберётся 5000 размеченных событий
  и 200 ранних скипов, она появляется.
- **`GET /api/status/skip-model`** — состояние модели: активна ли, сколько
  размеченных событий, сколько позитивов, AUC. Раньше было видно только
  глазами в `AppSetting`.
- Кнопка «запустить сейчас» в UI крона поддерживает новый тип задачи.

## 0.3.19

У волны появилась ФОРМА: разгон → вершина → спад.

- **Пачка больше не «плейлист с плавными переходами».** Раньше треки
  раскладывались по энергии МОНОТОННО (сначала тихо, потом громко — и до
  конца), то есть форма волны была отвергнута в коде явным комментарием
  («плавность важнее арки, поэтому монотонно»). Теперь пачка разгоняется,
  выходит на вершину и остывает.
- **Дуга живёт в муд-пространстве этапа 2.** Форму задаёт ИНТЕНСИВНОСТЬ
  (энергия + arousal + dance), а «цвет» трека (valence, dance) остаётся общим
  для пачки: дуга — это динамика, а не смена настроения. Пилюля при этом
  задаёт ПОЛ (жёсткий фильтр), а вершина — самая горячая трека пула.
- **Стык пачек не рвётся:** точка входа — звук текущего трека. Если
  пользователь уже слушает громко, волна не полезет ещё выше, а сойдёт.
  Мостик (key-сглаживание первого перехода) больше не может вытащить в
  начало трек другого динамического уровня.
- Настройки: `arc_on`, `arc_peak_pos` (где вершина), `arc_release` (насколько
  спад гасит динамику) — в тюнинге, группа «playlists».
- Если дугу строить не из чего (нет анализа, пул однородный) — старая
  раскладка по энергии, волна не пустеет.
- 12 новых тестов на форму волны.

## 0.3.17

Настроение волны стало ЧИСЛОМ, а не словом. Релиз объединяет два шага:
словарь настроений (он готовился как 0.3.16, но отдельным релизом не
выходил) и собственно числовое муд-пространство.

- **Пилюля «боевой» (и любое слово от LLM) теперь работает.** Настроения
  приходят из двух источников: librosa (9 слов) и LLM по тексту песни
  (свободные слова). Раньше неизвестное слово возвращалось «как есть»,
  пресет не находился, а жёсткий фильтр вырождался в «оставь треки с этим
  словом» → пул схлопывался → фильтр откатывался целиком. Итог: пилюля
  работала как «настроение не выбрано». Теперь нормализатор знает 15
  канонических кодов + таблицу подстрок (`боев`→`aggressive`,
  `тревож`→`tense`, `тоска`→`sad`…), а неизвестное слово честно
  игнорируется, а не ломает волну.
- **У всех 9 слов анализатора теперь есть пресет** (раньше 5 не имели:
  танцевальный, мечтательный, меланхоличный, тёплый, счастливый). Плюс
  новые `tense`/`romantic`/`epic`. `valence`/`dance`/`arousal` переехали из
  мягкого бонуса в жёсткий фильтр: «Счастливое» отсекает грустное.
- **Жанр без записи в таблицу выводится из данных** — муд большинства
  уже проанализированных треков этого жанра. Раньше `rap`/`hip-hop`/`pop`/
  `indie`/`lo-fi` в таблице не было, и такие треки проходили ЛЮБУЮ
  пилюлю: в «Боевое» попадал лоу-фай рэп.
- **Трек, не подтверждающий настроение, получает штраф** — раньше
  непроанализированные треки шли наравне с проверенными, и «Боевое»
  звучало вполсилы.
- **Настроение стало числом, а не словом.** Пилюля — это точка в
  пространстве звука (valence / energy / arousal / danceability) плюс
  радиус. Раньше настроение было строкой, и из этого следовало: «счастливое»
  и «бодрое» — почти синонимы, а смена настроения на ходу была скачком.
  Теперь у каждой из 15 пилюль есть свой центр и радиус (`MOOD_TARGETS`),
  а в ответе видно, что конкретно выбрано (`mood_target`, `mood_radius`).
- **Звук важнее слов.** Слова настроений от LLM — это про текст песни
  («боевая песня о любви»), а не про музыку. Теперь трек, который по звуку
  ровно в пилюле, проходит, даже если его слово чужое; а трек со словом
  «боевой», но спокойным звуком — отсекается рамками пресета.
- **Треки без анализа остаются в игре.** Пока идёт анализ, у трека нет
  вектора — но жанр известен, а жанр внутри библиотеки однороден по звуку.
  Мозг выводит вектор жанра по уже проанализированным трекам и оценивает
  трек с честной пониженной уверенностью: он может попасть в пачку, но не
  вытесняет проверенные треки и не получает штраф «не подтверждает».
- **Переход настроения — лестница, а не «голова/хвост».** Вместо бинарного
  градиента («стартовое → целевое») треки раскладываются по интерполяции от
  звука текущего трека к центру целевой пилюли: трек «наполовину грустный,
  наполовину поднимающийся» теперь существует.
- **Пачка больше не монолит.** Кап артиста (2 трека) и жанра (половина
  пачки) на отборе — но кап не ухудшает качество: трек под капом
  пропускается, только если есть альтернатива сопоставимого качества.
  Кап кода настроения работает, только когда пилюля не выбрана (с пилюлей
  одно настроение в пачке — замысел пользователя).
- **Градиент морфа перестал быть мёртвым**: сравнивался сырой лейбл
  ('спокойный') с каноническим кодом ('calm') — всегда False, обе группы
  пусты, «голова — стартовое, хвост — целевое» не строилось НИ РАЗУ,
  хотя API рапортовал `morph`.
- **Волна стала воспроизводимой.** Пул строится случайно (это нужно, чтобы
  мозг изучал библиотеку), но дальше решения зависели от порядка: дедуп
  «та же песня под другим row id» оставлял ПЕРВОГО, а штрафы за повтор
  артиста считались по порядку обхода. Теперь порядок детерминированный, а
  победителем дубля становится проанализированный (иначе его выкидывал
  mood-фильтр и песня выпадала из волны целиком).
- Каталог `/api/library/moods` отдаёт канонические коды + подписи + числовой
  центр пилюли, а фильтр `/api/tracks?mood=` понимает и код, и сырое слово —
  счётчик в дропдауне совпадает с выдачей.
- LLM больше не выдумывает свои настроения: закрытый словарь из 12 слов.
- Сиды выбираются сеяным генератором (был глобальный `random` — центроид
  «похоже на то, что ты любишь» гулял между одинаковыми запросами) и
  округление сидов больше не банковское (round(2.5) давал 2 вместо 3).
- Плеер: автопродление передаёт пилюли волны мозгу (раньше спрашивал вообще
  без контекста — вайб был слышен только в первой пачке), подписи
  канонических кодов в UI, чтение пилюль из одного места.
- 43 новых теста: словарь, муд-пространство, фильтр, лестница, разнообразие.
